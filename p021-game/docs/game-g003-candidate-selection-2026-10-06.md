# GAME-G003 Candidate Selection — 2026-10-06

## 目的

P021「ゲーム開発」の次サイクルとして、既存の GAME-G001「1マス農園」（資源・時間管理）と GAME-G002「過去の自分と協力するゲーム」（記録再生パズル）に重複しない新規PoC候補を3案比較し、次に実装する GAME-G003 を確定する。

共通前提:
- 5〜15分程度で主要な面白さを確認できる。
- スマートフォン／タブレットを主対象とし、Portrait / Landscape の両方へ対応できる。
- キーボードを必須にしない。
- Godot 4.7.2 / GDScript / Compatibility / Web single-thread を基本とする。
- DB、ログイン、課金、有料サービス、外部APIは使わない。
- 一般公開候補はP021の品質ゲートと素材ライセンス管理を適用する。

## 候補A — 風読みグライダー

**ジャンル:** 2.5Dアーケード・滑空アクション

プレイヤーは小型グライダーをタッチドラッグ／仮想スティックで操り、風の流れを読みながらゲートを抜けてゴールを目指す。上昇気流を拾うと高度とブーストを回復し、狭い危険ルートは高得点、広い安全ルートは安定走行というリスク／リターンを作る。

- 判断要素: 4/5
- 成長・変化: 4/5
- リプレイ性: 4/5
- スマホ縦横適性: 5/5
- Godot Web適性: 5/5
- 既存2作との差別化: 5/5
- 10〜15分PoC適性: 5/5
- 視覚演出の伸びしろ: 5/5

**合計: 47/50**

PoCでは3ステージ、各60〜90秒を想定。ステージごとに風向・ゲート配置・障害物を変え、ベストタイム／スコア／メダルを端末内保存する。奥行き感は重い3Dにせず、2.5D表現、パララックス、スケール変化、Particle2D等を中心に構成する。

## 選定結果

**GAME-G003 は「風読みグライダー」を採用する。**

理由:
1. 既存2作とゲームループが明確に異なり、P021の作例の幅を広げられる。
2. スマホのタッチ操作と相性がよく、Portrait / Landscape 双方へ展開しやすい。
3. Godot Webで重い3Dを使わずに、速度感・高度感・風・雲・飛行演出を表現できる。
4. 1プレイを短くしつつ、ルート選択、スコア、ベスト記録で判断要素とリプレイ性を両立できる。
5. 初期PoCの範囲を3ステージへ制限でき、一般公開品質まで段階的に改善しやすい。

## GAME-G003 初期定義

- ID: GAME-G003
- 名称: 風読みグライダー
- slug: `wind-reader-glider`
- ジャンル: 2.5Dアーケード・滑空アクション
- 主操作: タッチドラッグ／仮想スティック、PCは矢印/WASDを補助入力
- 1プレイ: 60〜90秒
- 初期PoC: 3ステージ
- 基本ループ: 発進 → 風を読む → ゲート通過／ルート選択 → 上昇気流・ブースト管理 → ゴール → スコア／メダル → 再挑戦
- 成功条件: 規定数の必須ゲートを通過してゴール
- 失敗条件: 高度または耐久を失いコースアウト
- 判断要素: 安全ルート vs 高得点ルート、ブースト使用、上昇気流の取り方
- 記録: ステージ別ベストタイム、ベストスコア、最高メダル
- 画面対応: Phone Portrait / Phone Landscape / Tablet Portrait / Tablet Landscape
- コスト: 無料構成。外部素材を採用する場合はCC0等を優先し、ASSETS.mdで追跡する。
