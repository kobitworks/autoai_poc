# P021 ゲーム一般公開品質基準・素材利用ルール v1.0

対象: P021で生成・公開するすべてのゲーム  
初版: 2026-10-05  
適用開始: GAME-G001 / GAME-G002 の全面リファインから

## 1. 基本方針

P021では「動作するPoC」と「一般公開可能な試遊版」を分けて扱う。
公開完了にするには、ゲームループの成立だけでなく、見た目、導線、操作感、演出、音、説明、レスポンシブ、ゲームバランスを含めて最低品質を満たすこと。

初期検証中は図形・仮テキストを許容するが、公開版では原則として仮素材を残さない。
可能な限り、利用条件を確認できる高品質なフリー素材を用い、ゲーム全体のアート方向を統一する。

## 2. 公開判定チェック

### A. ファーストビュー
- ゲーム名と目的が一目で分かる。
- ロード後に「何をすればいいか」が5秒以内に判断できる。
- タイトル/開始/遊び方の導線がある。
- デバッグ文言、仮ボタン、仮図形が目立つ状態で残っていない。

### B. アート・UI
- 背景、キャラクター、地形、主要オブジェクト、UIアイコンに統一感がある。
- 色だけに依存せず、形・アイコン・ラベルでも状態を識別できる。
- ボタンに通常/押下/無効などの状態差がある。
- 文字と背景のコントラストを確保する。
- 日本語が欠けないフォントを使用する。
- PC/スマホ双方でUI重なりや文字切れがない。

### C. 操作性
- PC操作とスマホ操作の両方を明示する。
- タップ領域は小さすぎない。
- 入力時に視覚または音でフィードバックする。
- リトライ/やり直しを迷わず実行できる。
- ゲーム開始直後に説明なしで詰まる状態を作らない。

### D. ゲーム内容
- 目的、失敗条件、成功条件が明確。
- 1プレイ内に「判断→行動→結果」のフィードバックがある。
- 待ち時間だけで進む時間を極力減らす。
- 初見で理解できる導入と、小さな達成感を入れる。
- 1ステージだけでも、単なる技術デモではなくゲームとして成立させる。
- 必要に応じてチュートリアル、複数ステップ、スコア、評価、報酬、演出を追加する。

### E. 演出・音
- 重要操作に押下/移動/取得/成功/失敗などの反応を付ける。
- クリア時は通常状態と明確に異なる演出を出す。
- 可能なら効果音を付ける。BGMはゲームに合う場合のみ導入する。
- 音量を上げすぎず、ブラウザ自動再生制限を考慮する。

### F. Web品質
- Godot Web Exportが正常完了する。
- 公開URLでロードできる。
- 実ブラウザで描画・入力・画面遷移を確認する。
- 主要画面で致命的なコンソール/ロードエラーがない。
- 960x640固定前提だけに依存せず、小さい画面でも操作できるよう調整する。

## 3. 素材ソース方針

### 優先度A: Kenney
- URL: https://kenney.nl/assets
- ライセンス: 各アセットページのゲーム素材はCC0。
- 商用利用: 可。
- クレジット: 不要。ただし任意で "Kenney" と記載可。
- 用途: 2Dキャラクター、タイル、UI、アイコン、背景、パターン、フォント等。
- P021では最優先候補とする。

### 優先度B: Game-icons.net
- URL: https://game-icons.net/
- ライセンス: CC BY 3.0。
- 商用利用: 可。
- クレジット: 必須。原作者名とGame-icons.netをCreditsへ記載する。
- 用途: HUD、能力、状態、操作、資源、建物などの補助アイコン。

### 優先度B: OpenGameArt
- URL: https://opengameart.org/
- ライセンス: 素材ごとに異なる。CC0、CC BY、CC BY-SA、OGA-BY、GPL等。
- 商用利用: 掲載ライセンスに従えば可能。
- P021では原則 CC0 を優先し、次点で OGA-BY/CC BY を採用する。
- CC BY-SA / GPL は派生物・配布条件が複雑になるため、明確な理由がない限り使用しない。
- 個別素材ページのライセンス・作者・URLを必ず記録する。

### 音素材: Freesound
- URL: https://freesound.org/
- ライセンス: 音源ごとにCC0 / CC BY / CC BY-NC等。
- P021ではCC0を優先し、CC BYはクレジット管理できる場合のみ使用する。
- CC BY-NCは将来の広告・有償公開と衝突するため使用禁止。

### フォント
- 日本語フォントはGoogle Fonts等でライセンスが明示されたものを使用する。
- 既存のNoto Sans JPなど、Web/Godotで安定表示できるものを優先する。
- フォントファイルの再配布条件も確認する。

## 4. 原則使用禁止

- 出典不明の画像・音源。
- Google画像検索等から直接保存した素材。
- 「フリー素材」とだけ書かれ、ライセンス条件が確認できないもの。
- NC（非営利限定）素材。
- ND（改変禁止）でゲーム組込み条件が不明瞭な素材。
- 作者不明・転載サイト経由のみの素材。
- 他ゲーム、アニメ、漫画、映画等の著作物を模倣・転載した素材。
- ライセンス確認前の生成物を「フリー素材」とみなすこと。

## 5. 素材台帳

各ゲームのソース配下に `ASSETS.md` を置き、外部素材を1件ずつ記録する。

必須項目:
- asset_id
- 使用箇所
- 素材名
- 作者
- 配布元URL
- 取得日
- ライセンス名
- 商用利用可否
- 改変可否
- クレジット要否
- クレジット文
- ローカル配置先
- 備考

CC0でも出典追跡のため台帳には記録する。

## 6. Credits

クレジット必須素材が1件でもある場合、ゲーム内またはゲーム一覧から到達できるCreditsを用意する。
最低限、作者、素材名、ライセンス、配布元を表示する。
ゲーム内表示が難しい場合は `CREDITS.md` とWebページ上のCredits導線を両方用意する。

## 7. リファイン工程

1. 現行版を実ブラウザでレビュー。
2. 問題を「アート/UI/操作/ゲーム性/演出/音/レスポンシブ」に分類。
3. アート方向を1つ決める。
4. 必要素材リストを作る。
5. 素材候補を調査し、ライセンス確認。
6. ASSETS.mdへ登録。
7. Godotへ素材を組込み、画面レイアウトを再設計。
8. チュートリアル/操作フィードバック/クリア演出を追加。
9. 難易度・テンポを調整。
10. PC/スマホで試遊。
11. CI Web Export。
12. GitHub Pages公開。
13. 実ブラウザ確認。
14. 公開品質チェックを満たした場合のみタスクDone。

- 初回チュートリアル。

- クリア演出を強化。

## 9. 完了定義

以下をすべて満たして「一般公開可能」と判断する。
- 仮素材が主要画面に残っていない。
- 素材ライセンス台帳がある。
- 必須クレジットが表示される。
- 初見ユーザーが遊び方を理解できる。
- PC/スマホで操作できる。
- ゲームとして1回以上の明確な達成体験がある。
- 主要操作にフィードバックがある。
- クリア/失敗/リトライ導線がある。
- CIが成功。
- 公開URLを実ブラウザ確認済み。
